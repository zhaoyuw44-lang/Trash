Google Antigravity CLI · 本地阅读稿

在终端里用 agy

先看清你在拧哪三个旋钮，再决定这一次要不要让它自己改文件。

Antigravity CLI 是 Google Antigravity 的终端界面（TUI）。二进制就叫 agy。它能读仓库、改文件、跑命令、派子代理（subagent），也能被脚本以无头方式调用。这份说明按 2026-11-19 的官方文档整理。产品在改，你机器上的 agy --help 和会话里的 /help 优先于这里的任何一张表。

用浏览器直接打开这个文件即可。不需要本地服务器。官方安装与参考：Getting started · CLI reference

只看这一段也能开工

  1. 在项目目录里运行 agy。信任提示指的是：允许它在这个目录里读、改、执行。不要在家目录里点 Yes。
  2. CLI 1.5.7 起，沙箱可用且是个人账号时，启动模式是 auto：工作区里的编辑直接落盘，命令默认进终端沙箱（terminal sandbox），需要跑到沙箱外的命令会先被评估，不可逆的仍会停下来问你。
  3. 不熟的仓库用 agy --mode=plan。想看每一处 diff，用 Shift+Tab 转回 default，直到状态栏上的模式字消失。
  4. 跑偏时按 Esc 或 Ctrl+C 打断这一轮。/rewind 把对话退回早先某条。/clear 会重置上下文。Ctrl+L 只重画屏幕。
  5. 脚本用 agy -p。回答在 stdout，诊断在 stderr。先开一次交互会话完成登录。无头模式下，本来该问你的工具会被软拒绝（soft-deny），进程仍可能以 0 退出。
  6. 细规则写成 action(target)，例如 command(git diff)。拒绝（Deny）高于询问（Ask），询问高于允许（Allow）。command(git) 盖不住 git log $(whoami) 这种带命令替换的行，那种行会退回询问。
  7. 模型目录会变。用 agy models 抄 slug。无头模式下写错模型会直接失败，不会悄悄换一个。

先分开三样东西

应用、CLI、SDK 不是同一个开关

同一个 Google 账号可以打通 Antigravity 的几处入口，但权限预设的名字并不互通。把桌面应用里的 Turbo 当成 CLI 的 auto，是最常见的误配。

旋钮 1 · 执行模式

agentMode

default、accept-edits、auto、plan。决定这一轮对工作区编辑和要不要先写计划的姿态。会话中按 Shift+Tab 循环，或启动时加 --mode。

旋钮 2 · 工具许可

toolPermission

request-review（默认）、proceed-in-sandbox、always-proceed、strict。这是全局安全预设，叠在细规则上面。strict 会压过 auto，连读文件也要问，Allow 规则也压不住。

旋钮 3 · 沙箱

终端沙箱

操作系统级隔离，不是第四种执行模式。macOS 用 sandbox-exec，Linux 用内核命名空间，Windows 用进程安全环境。auto 会自己打开它。其它模式用 --sandbox 或 enableTerminalSandbox。

应用文档里的四档预设是 Request Review、Default、Auto、Turbo。CLI 没有名为 Turbo 的模式。应用的 Turbo 关掉沙箱、放行命令和全盘文件，接近 CLI 的 always-proceed，不是 auto。CLI 的 auto 仍然把命令关在沙箱里，出沙箱的高风险动作会停下来问。

第一次

装好、登录、只信任这个仓库

1

安装

官方一键安装会把脚本直接送进 shell。想先看脚本，就先下载再执行。Windows 用 PowerShell 的 irm … | iex，或 CMD 的 install.cmd。二进制默认落在 ~/.local/bin/agy（Windows 为 %LOCALAPPDATA%\agy\bin）。

curl -fsSL https://antigravity.google/cli/install.sh -o /tmp/agy-install.sh
# 读完再执行
bash /tmp/agy-install.sh
agy --version
2

让 shell 找得到它

安装器有时加不进 PATH。官方排错页写的是 export PATH="~/.local/bin:$PATH"。双引号里的 ~ 在 bash 里不会展开，这一行会失效。用 $HOME。

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
agy --version
3

在项目目录里启动，完成登录

令牌进系统钥匙串（macOS Keychain、Linux secret-service、Windows Credential Manager）。本机会打开浏览器。SSH 上它改为打印一个要在本地浏览器打开的链接。/logout 会清掉保存的凭证。也可以用 Google Cloud 项目登录；把请求直接打到 Gemini API 时，在设置里把 modelProvider 设为 gemini，并提供 GEMINI_API_KEY。

mkdir -p ~/src/agy-demo && cd ~/src/agy-demo
agy
4

第一次还会问两件外观上的事，然后问你信不信任这个目录

配色和渲染模式可以以后在 /config 里改。渲染模式 default 把对话留在当前终端滚动区，全屏面板才用备用屏幕；always 整页都在备用屏幕里，关掉后上面的输出不进 shell 历史。信任会写进 ~/.gemini/antigravity-cli/settings.json 的 trustedWorkspaces。你点过 Yes 的目录，下次不再问。

5

给一个收得回来的第一句

官方入门示例是让它写一个抓取网页正文的 Python 脚本。在 default 下，创建文件前会要你确认；在 auto 下，工作区写入和沙箱内命令会自己进行。看完用 /diff。离开用 /exit，或在空提示框上按 Ctrl+D。

更新用 agy update。CLI 自己也会在后台检查更新，锁文件在 ~/.gemini/antigravity-cli/updater/。不想自动更新：export AGY_CLI_DISABLE_AUTO_UPDATE=true。

这一次

按你现在的处境启动

模式可以中途换。启动时选对，是为了让第一轮就处在你真的看得住的松紧上。

启动

agy --mode=plan

plan 会在你的提示前加上 /plan。它先用只读搜索和读文件摸清代码，写出一份实现计划等你点头，然后再改。需求自己也没想清时，进去第一句用 /grill-me：它一题一题问，每题附一个建议答案。

公司账号或这台机器没有沙箱时，auto 不会出现。plan 不受这个限制。

启动

agy --mode=default

改文件前给你一份带语法高亮的 diff。已有文件：1 接受，2 拒绝，f 打开全屏 diff。拒绝时把焦点放在 No 上，按 Tab 可以写“改成这样”，再按 Enter。这条确认不会被 Esc 关掉。新文件的面板上，Esc 等于拒绝创建。

1.5.7 起默认可能已是 auto。状态栏右下角没有模式字，才是 default。

启动

agy --mode=accept-edits

工作区里的创建、修改、替换直接落盘，后台 subagent 的写入也继承这个模式，不会在队列里等你。终端命令仍然按权限预设询问。适合你信得过这批编辑、但还想亲手放行每一条 shell。

启动

agy

个人账号、沙箱可用、CLI 1.5.7+ 时，这就是 auto，不必再写 --mode=auto。工作区编辑自动通过。命令默认在沙箱里跑，沙箱默认只能看见工作区和临时目录，默认没有网络。必须出沙箱的命令会先被评估：构建、测试、lint、格式化这类可逆动作可以自己跑，不可逆或高风险的仍会问。

可用范围：macOS / Linux 自 CLI 1.3.5，Windows 自 1.4.4。Windows 沙箱需要 Windows 11 24H2 且含 2026 年 8 月的更新。企业账号没有 auto；--mode=auto 会落到 default，无头模式会先打印警告。

启动

agy -p "用一句话说明 git rebase 做什么"

问完即退出，没有后续回合。回答在 stdout。想接着问，加上 -c（继续最近一次对话）或 --conversation <id>。想打开 TUI 并带上第一句，用 agy -i "…"，会话会留下来。

启动

agy -p "列出这个仓库的测试命令" --output-format json

先在有终端的环境里交互登录一次。CI 上没有缓存凭证时，它会以 authentication required 退出，而不是挂起等你。本来要弹确认的工具会被软拒绝：退出码仍可能是 0，说明写在 stderr。要放行，事先写 permissions.allow，不要图省事加 --dangerously-skip-permissions。

进会话之后

/goal 为 parser 补上空输入测试，并让 npm test 通过

/goal 会一直做到目标被验证完成，中间不再停下来问你下一步。所以目标里要有你机器上真能跑的检查。仓库还不熟时，先用 plan 把范围圈住，再下 goal。想看它中途有没有跑偏，Esc 仍然能打断。

一轮里实际发生什么

你写提示，它调用工具，你来批准

1

工作区就是你启动时所在的目录

额外目录用 /add-dir 或重复的 --add-dir。工作区外的读写默认要问；allowNonWorkspaceAccess 默认关着。创建工作区外的文件时，面板会多一个“始终允许工作区外访问”。那是持久放宽，不是这一次的例外。

2

你写任务。需要钉死文件时用 @

输入 @ 会补全路径，agent 拿到的是完整路径。截图用 Ctrl+V 贴进提示框。多行用 Shift+Enter、Ctrl+J 或 Alt+Enter。长提示按 Ctrl+G，会交到 $EDITOR（设置项 editor，默认 auto）。

3

它读规则，再调用工具

仓库根上的 AGENTS.md 或 GEMINI.md 会在启动时被读走。工具包括读文件、改文件、跑命令、网页、MCP、以及后台 subagent。每一动都过权限引擎。觉得它“什么都没做”时，按 Ctrl+O 展开工具轨迹，或把 /config 里的 Verbosity 调到 high。

4

你在旁边看，而不是等它结束再看

命令确认是 y / n。正在等你批准一条命令时，Ctrl+G 的含义变了：它在 CLI 内部打开全屏编辑器，让你改完命令再批准，这时它不会去叫外部编辑器。subagent 卡在确认上时，Alt+J 跳到下一个，Ctrl+K 批准状态栏里那一条。

5

生成途中你又打了一句

默认 queuedMessages 是 queue：这句话等到当前回合结束再送。设成 send-immediately 则会打断当前回合。 Alt+M 走与当前设置相反的那一条。

范围是空的

修一下登录

它会自己猜文件、自己猜“修好”的标准，然后在 auto 里把猜测写进磁盘。

结果、边界、检查都在

超时后仍显示成功

只改 src/auth/session.ts 和它的测试。先写一条失败测试，再改实现，最后跑 npm test。失败就停，把摘要贴出来。不要动迁移。

执行模式

四个模式各放行什么

循环顺序是 default → accept-edits → auto → plan → default。没有 auto 的环境会从 accept-edits 直接到 plan。状态栏写出当前的非 default 模式。default 正在等文件确认时，Shift+Tab 会切到 accept-edits 或 auto，并接受尚未确认的工作区写入。

default

先看 diff，命令也问

适合敏感重构。设置里写成 "agentMode": ""。文件确认用 1 / 2 / f，不是 y / n。

accept-edits

编辑放手，命令仍问

工作区内的 write_to_file、替换类编辑自动通过。shell 仍走 toolPermission 和细规则。

auto

编辑放手，命令进沙箱

出沙箱前先评估。可逆的开发命令可以自己跑，不可逆的仍问。企业账号和没有沙箱的机器上看不到这一档。

plan

先写计划再改

提示会被加上 /plan。已经处在 plan 时，不必再手打一遍。旧的 /planning 和 /fast 在 1.1.0 移除了。

细规则压过模式。 /permissions 里的 Deny、Ask、Allow，以及 --dangerously-skip-permissions 和 strict，在四种模式里都生效。plan 不是“只读锁”：文档说计划阶段用只读搜索和读文件，但命令仍然经过同一套权限。

启动标志是 --mode，没有 --permission-mode。沙箱也不会出现在 Shift+Tab 的循环里。要持久改默认：/config 里改 Agent Mode，立刻写入 settings.json。省略 agentMode 时，可用环境下从 1.5.7 起按 auto 启动。

权限引擎

一条动作怎么被裁判

每个敏感动作都是 action(target)。动作有 read_file、write_file、read_url、execute_url、download_url、command、mcp。企业账号的旧规则里还有单独的 unsandboxed。写路径隐含读同一路径；拒绝读则同时拒绝写。

命中顺序。上面的赢。
层结果
Deny任何模式都直接挡住，包括沙箱里本来能跑的命令。
strict连读文件也要问，即使 Allow 写了这条。它压过 auto。
Ask比 Allow 优先。文档里的例子：Ask 里有 command(*)，Allow 里有 command(git)，结果是每条命令都问。
--dangerously-skip-permissions本会话按 always-proceed 自动批准工具请求，包含写文件和执行命令。Ask 和 Deny 仍然算数。无头文档明确建议只在你完全信任提示和环境时使用。
Allow精确放行，不再问。
模式与预设的默认上面都没写到时：工作区内读写通常放行；网页和 MCP 默认问；命令在 request-review 下问，在沙箱开启且 proceed-in-sandbox 或 auto 下，沙箱内放行。

前缀匹配会在这些写法上关掉

Allow 里的 command(git) 按词前缀匹配。git status && git log 可以放行。一旦出现命令替换 $(…)、反引号、进程替换、算术扩展、花括号展开、非字面命令名、网络或文件描述符重定向，以及会执行子命令的参数（如 git -c core.pager=…、tar --to-command），整行改为必须和规则逐字相同，否则退回询问。git log $(whoami) 因此不会被 command(git) 静默放行。

Allow：command(git)

git status && git log

放行。管道、&& / || / ;、引号、普通 $VAR、简单文件重定向，以及 timeout、env 这类透明包装，仍然走前缀匹配。包装内部的命令会再评一次。

Allow：command(git)

git log $(whoami)

询问。前缀匹配被关掉。除非有一条规则和整行逐字相同，或 regex: 规则覆盖原始整行。

Ask：command(*)　Allow：command(git)

git status

询问。Deny > Ask > Allow。通配的 Ask 会盖住更具体的 Allow。想少问 git，就要拿掉这条 Ask，而不是再加一条 Allow。

Allow：command(git push)

git push

放行，并且可以在沙箱外跑，因为 push 需要网络，而沙箱默认没有网络。command(git) 会把 status、commit、reset、push 一起放进来。希望 push 仍由你点头时，只写 command(git status)、command(git diff)、command(git log) 这种更短的前缀。

没有细规则，沙箱开着

npm test

沙箱内：auto 与 proceed-in-sandbox 下直接跑。沙箱外：default / request-review 会问；auto 会先评估，可逆的放行，不可逆的问。沙箱在这台机器上不可用时（CLI 1.4.4 起），--sandbox 没有效果，proceed-in-sandbox 退回 request-review 的行为。

一份偏紧、但日常能用的设置

文件在 ~/.gemini/antigravity-cli/settings.json。项目级、各 Antigravity 产品共享、以及全局，是 /permissions 里的三个范围。交互面板里 A 添加，E 编辑，D 删除，左右键切换 allow / deny / ask。手改 JSON 后若启动报错，用 /config 改回去更稳。编辑器可加 schema 做校验。

{
  "$schema": "https://antigravity.google/schemas/v1/settings.json",
  "agentMode": "accept-edits",
  "enableTerminalSandbox": true,
  "toolPermission": "proceed-in-sandbox",
  "notifications": true,
  "verbosity": "medium",
  "permissions": {
    "allow": [
      "command(git status)",
      "command(git diff)",
      "command(git log)",
      "command(regex:npm run (build|lint|test))"
    ],
    "deny": [
      "command(sudo)",
      "command(rm -rf)",
      "write_file(.git/)"
    ]
  }
}

沙箱的文件系统白名单来自这些规则：write_file 的路径可写，read_file 的路径只读，其余不可见（Windows 上用户配置目录之外的文件夹仍可读）。read_url 的域名会进入沙箱的出站名单，所以它同时放行“抓网页 markdown”和沙箱里的 curl / npm。浏览器 subagent 打开页面看的是 execute_url，read_url 不算数。localhost 按端口分开，mail.google.com 这类敏感 Google 子域要单独写规则。

坐在终端前

每天真的会用到的命令

在提示框里打 / 会出补全。Tab 接受高亮项。下面按你要做的事分组。完整名单在文末，可搜索。

看

/diff · /context · /usage

/diff 按轮次、改动和提交看差异。Ctrl+R 或 /artifact 审计划之类的产物：y / n 单条，Shift+A 全部接受，Shift+R 全部拒绝，p 预览，Esc 提交审阅结果并返回。/context 看上下文窗口占了多少。/usage（别名 /quota）看配额，/credits 看额度。

问一句，不岔开主线

/btw · /copy

/btw 这个函数是谁调用的？ 在后台回答，不把主对话带跑。/copy 复制上一条回答，/copy 2 复制倒数第二条，/copy btw 复制最近一次旁问。

想清楚再动手

/plan · /grill-me

/plan 先勘察、澄清、写出可审阅的实现计划。产物审阅策略 artifactReviewPolicy 默认 asks-for-review，它会等你。这个键不影响文件编辑本身。/grill-me 适合需求还糊的时候。

放手，但要有终点

/goal · /boost · /effort

/goal 做到可验证完成才停。/boost 做一轮多 agent 深度推理，比普通一句更重。/effort 调当前模型的推理力度，TUI 文档的范围是 low 到 max，视模型而定；无头文档的例子用 low、medium、high。以补全和 agy --help 为准。

平行与外部

/agents · /tasks · /browser

/agents 切换自定义 agent，并看后台 subagent。/tasks 看后台 shell 日志。/browser 把网页核对和浏览器里的调试交给 browser subagent。/swarm 起一组具名 worker 加一个 verifier，共用消息板，Alt+S 打开板。/teamwork 面向长周期协作，文档标明付费方案。

会话本身

/resume · /fork · /rewind

/resume（/switch、/conversation）打开历史。启动时继续最近一次用 agy -c，指定 id 用 --conversation。/fork 克隆当前线程去试另一条路，不行就 /resume 回来。/rewind 退回早先某条消息。/rename 给线程起名，免得选择器里全是 Untitled。

同一个键

先看你处在哪种场合

键位可以在 /keybindings 里改。下表是默认绑定在文档里写明的行为。选场合，再选键。

正在生成 · Esc

打断这一轮，停掉正在流出的文本，把提示框还给你。打开页面后可以选择场合和按键。

Ctrl+G 有两义

平常它打开外部编辑器

用来写长提示，编辑器由 editor 设置或 $EDITOR 决定。当 agent 正在请你批准一条命令时，同一个键改为在 CLI 内部把命令展开成全屏文本，让你改完再批准。这一义是固定的，不调用外部编辑器。

Ctrl+K 不是命令面板

它批准等待中的 subagent

应用里的 Ctrl+K / Cmd+K 用来搜会话。CLI 里搜历史会话是 /resume。Ctrl+K 会立刻批准状态栏提示的那条 subagent 动作。从别的工具带过来的肌肉记忆会在这里误批准。

Ctrl+L重画并清掉视觉缓冲。对话还在。

Vim 编辑是另一套：editorMode 设为 vim 后，提示框变成模态编辑。它和“用哪个外部程序”的 editor 不是同一个键。vimInsertFirst 为 true 时，从插入模式开始，单独的 Enter 会提交。

无头模式

给脚本和 CI 用的是另一个契约

-p、--print、--prompt 是一回事：跑完一条提示就退出。stdout 只有回答，错误、登录提示、进度和权限通知在 stderr。因此可以安全地写 answer=$(agy -p "…")。

text

给人看

默认。回答原文，不加包装。

json

给程序收尾

结束时一行 JSON。response 是文本，conversation_id 用来续聊，status 是终态，usage 里有输入、输出、思考和缓存 token。

stream-json

边跑边看

NDJSON。先一条 init，然后若干 step_update（含工具的 tool_info），最后一条 result。

agy models
agy -p "用一句话说明这个仓库怎么跑测试" \
  --output-format json \
  --model gemini-3.8-flash-medium \
  | jq -r '.response'

--model 后面的字符串从 agy models 第一列抄。上面的 gemini-3.8-flash-medium 只是无头文档里出现过的样子，不是一份稳定目录。写错时无头模式不会悄悄换默认模型：退出码非 0，status 为 ERROR，错误文本里带上当前可用模型。

结构化输出

--json-schema 接受 JSON 字符串、schema 文件路径，或 string / number / integer / boolean。解析后的对象在 structured_output，response 仍是它的字符串形式。

agy -p "把 v2.14.3 拆成整数 major、minor、patch" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"major":{"type":"integer"},"minor":{"type":"integer"},"patch":{"type":"integer"}},"required":["major","minor","patch"]}' \
  | jq '.structured_output'

多轮放在同一个进程里

--continue 每次都是新进程，能接上上下文，但会重复启动。--input-format stream-json 从 stdin 逐条喂提示，必须配 --output-format stream-json。每条用户消息是一行 {"event":"user","message":{"content":"…"}}。内容块只允许 text。关掉 stdin 才会在当前回合结束后退出。在收到本轮 result 之前写出下一句，或者等进程退出才去读 stdout，都会卡死或丢中间回合。

流里不要塞 /model、/usage 这种由 CLI 自己回答的斜杠命令。 会话会以错误结束，退出码 2。它们要单独跑，例如 agy -p /model。同时，-p 带上的提示在 stdin 流模式下会被丢掉，提示只能来自 stdin。

退出码和“它其实没做”

status含义
SUCCESS跑完并给出了回答。工具被软拒绝时也可以是它，退出码 0。
ERROR失败。未知模型、坏的流输入等。退出码非 0。
CANCELED / INTERRUPTED取消，或例如收到 SIGINT。
WAITING停在等待输入。
INVALID / RUNNING非法状态，或没有走到终态。

工作区内的读写默认放行。shell 这类默认要问的动作，在无头模式里无人可问，于是软拒绝，并在 stderr 写明工具名和怎样放行。检查 CI 时要同时看 status 和 stderr，不能只看退出码。

#!/usr/bin/env bash
set -euo pipefail
result=$(agy -p "根据 package.json 写出测试命令，不要改文件。" \
  --output-format json \
  --print-timeout 10m)
status=$(jq -r '.status' <<<"$result")
if [[ "$status" != "SUCCESS" ]]; then
  jq -r '.error' <<<"$result" >&2
  exit 1
fi
jq -r '.response' <<<"$result"

超时有两处文档：无头指南写默认最多等 5 分钟，--print-timeout 15m 可以放宽；命令参考表把同一标志的默认写成 0s，并说明 0 表示等到本轮结束。以你安装的 agy --help 为准。

选模型和 agent：agy models、agy agents，再用 --model、--agent、--effort。slug 看起来会像 gemini-3.8-flash-medium 这种字符串，目录本身会变，不要从旧文章里抄。

第二次就不必再解释

把纠正留在仓库里，而不是留在聊天里

1

仓库根放 AGENTS.md 或 GEMINI.md

写测试命令、不能动的目录、风格、已废弃的入口。agent 启动时会读。这比每次在提示里重复更稳，也比把个人习惯写进全局规则更不容易污染别的仓库。

2

同一类纠正出现第二次，用 /learn

它把这次会话里的纠正收成一条 rule 或 skill 提案，给你审，而不是悄悄改掉你的配置。

3

技能、插件、MCP、钩子走各自的命令

/skills 查看，/skills reload 从磁盘重载。/plugin 可以 install / uninstall / enable / disable / list。/mcp 管 MCP server。/hooks 看 pre-flight 和 post-format 脚本。不确定该改哪一种时，用 /agy-customizations，它会把官方的定制说明载进来再动手。CLI 自己怎么用，问 /antigravity-guide。

4

给它一个能自己跑的检查

官方最佳实践把这件事放在提示技巧之前：仓库里要有测试、构建或格式化命令。没有就先让它补测试。然后要求它跑，并根据输出自己改。没有这个环，auto 和 /goal 只是更快地写完未经检验的改动。

文档里已经点过名的

这些地方和直觉相反

在 $HOME 点了信任

信任按目录记住。家目录被信任之后，之后从家目录启动都会带着读、改、执行的许可。只信任具体仓库。

用 Shift+Tab 来“跳过”diff

确认文件修改时，它会切换到更松的模式并接受排队中的工作区写入。拒绝用 2。

无头模式只看退出码

软拒绝仍是 0。该跑的测试可能根本没跑。看 stderr，或事先写 Allow。

command(git) 当作“只读 git”

前缀会盖住 push、reset、commit。出沙箱的 push 若被 Allow，就不再问你。

企业账号上写了 --mode=auto

auto 不提供。CLI 改以 default 运行。无头模式会警告。不要在 CI 脚本里假设 auto 生效。

沙箱不可用却打开了 proceed-in-sandbox

1.4.4 起这会表现成 request-review。Windows 10、较旧的 Windows 11、禁掉非特权用户命名空间的 Linux 容器，都可能没有沙箱。

钥匙串在 SSH / 无界面 Linux 上是锁着的

症状是启动卡住，或 secret keyring is locked。macOS 需要解锁 login keychain。Linux 需要可用的 D-Bus 会话和钥匙串守护进程。无头环境先在交互会话登录一次。

SSH 里贴不进截图

图形剪贴板不走普通 SSH 流。iTerm2、Ghostty 和 OSC 52 才能把图片送进 Ctrl+V。tmux 里要 set -s set-clipboard on。

更新锁把启动挂住

提示 update.lock 时，锁在 ~/.gemini/antigravity-cli/updater/update.lock。确认没有正在更新的进程后可以删掉这个锁。安装目录需要你的用户可写。

备用屏幕让你找不到滚动记录

那是 altScreenMode: always。改成 default 后，对话留在终端自己的滚动区里。全屏面板仍会临时用备用屏幕。

从博客抄了一串模型名

动手实验文档（2026-09）里的模型表已经不能当目录。用 agy models。交互式 /model 的选择会写进设置并保持；单次换模型而不改默认的参数形式，以 / 补全为准。

把应用的权限截图拿来配 CLI

Turbo、Request Review 是应用预设。CLI 里对应去拧的是 agentMode、toolPermission、enableTerminalSandbox 和 permissions。
